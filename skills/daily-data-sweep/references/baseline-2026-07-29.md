### Detail behind the banking rows

- **Balance verification.** `account_balances` exposes first-class verification fields
  (`verification_error`, `verification_error_detail`, `verified_at`, `verification_last_run_at`,
  `calculated_balance_diff` vs `expected_balance_diff`). The 6 failing rows include *"Balance
  mismatch: expected 10498.53, calculated 9448.53, difference 1050"* on Mercury Credit (USD), and
  *"expected 0, calculated 28876.02"* on Mercury Checking. `verified_at` is null on all 6. The 1,050
  case trips **both** arms of tolerance 6b (1,050 absolute = 10.0% of 10,498.53).
- **A zero-amount transaction exists.** A Reddit Ads row carries `instructed_amount:
  {amount: 0, EUR}` — grounding `BANK-txn-amount-nonzero`. (Moved here from the banking
  control-point file, which now carries the condition only.)
- **Uncategorized transactions.** The 788 nulls span three distinct `category_status` values —
  `classifier_failed`, `classifier_abstained`, and null (never attempted). Several of those rows also
  have a null `booking_date`. The three causes route to different fixes and must never be collapsed
  into one number.
- **Duplicate account ingestion.** The ~24 duplicate rows are all "Compte principal" (EUR, `deposit`,
  via the Qonto (FR) connector `plaid_ins_137879`, workspace WellappFR `1c5c706f`), with `created_at`
  values spaced almost exactly **one hour apart**, from 2026-07-27T16:37 through 2026-07-28T15:01.
  That cadence is the sync interval, so the sync is **inserting a new account row per run instead of
  upserting**.
- **Accounts with no currency.** 3 rows (`"active"`, `"Mercury Savings ••0729"`,
  `"Mercury Checking ••9282"`, all `type: other`, via the `mercury-mcp` connector) have
  `currency: null` — and they appear to be the *same* Mercury accounts already ingested via the Plaid
  Mercury connector (`plaid_ins_116794`), i.e. a cross-connector duplicate as well.
- **`accounts.workspace_connector_pk` is null on all 30 rows** even though the source connector
  resolves through `sourceWorkspaceConnector` — the direct FK is unpopulated.
- **Connector statuses.** `workspace_connectors.status` carried live values beyond `enabled` across
  17 connections in the 3 workspaces: **`to_configure`** (Airtable, Circleback) and **`degraded`**
  (Attio, Xero).
- **Journal entries.** 117 rows total, sourced from Xero (WELL APP INC.) and Pennylane (WellappFR) —
  the accounting graph is populated in 2 of 3 workspaces and empty in the third.
- **33 queryable roots** confirmed via `well_get_schema()`; `enrichment` provenance is available per
  field and should be cited by each control point.

## Two live defects worth their own bug, independent of this skill

1. **Duplicate hourly account ingestion** — ~24 rows of one account, detailed above.
2. **Own-company misclassification** — WellappFR's own company tagged `company_origin: counterparty`.
   This is only a defect if `workspaces.own_company_pk` points at the wrong row; `company_origin` is
   per-company and legitimately differs across workspaces. See `schema-facts.md`.

A third is **suspected but unconfirmed**: if credit notes (`document_type_code: 381`) are stored with
a positive `grand_total`, every credit note inflates AP and AR across four skills. One targeted query
settles it — do that before filing.
